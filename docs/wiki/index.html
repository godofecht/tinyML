Welcome

This wiki renders the project documentation and blog posts in one place.

Why Build This When TensorFlow Exists?

TensorFlow is excellent for training and large-scale deployment, but tinyML targets a different set of constraints: ultra-low latency, tiny memory budgets, and predictable performance on edge CPUs. This project exists to push real-time inference into places where full ML stacks are too heavy.

What tinyML Is Better At

  • Sub-millisecond inference on CPU-only devices
  • Tight memory footprints for embedded and mobile targets
  • Deterministic latency for real-time systems
  • Focused, optimized kernels instead of general-purpose graphs

Potential Use Cases

  • On-device personalization and adaptive inference
  • Streaming and real-time signal processing
  • IoT analytics with strict power and memory limits
  • Privacy-sensitive workloads that must stay on-device

How tinyML Compares

RTNeural

RTNeural is a focused real-time inference engine for audio DSP use cases. tinyML covers a broader range of model families (attention, transformers, GNNs, PINNs, RL) and targets a wider set of edge applications beyond audio, while still prioritizing real-time CPU performance.

ANIRA

ANIRA is tailored to specialized audio neural rendering pipelines. tinyML aims to be more general-purpose for edge inference across domains, while retaining the real-time focus that audio applications demand.

ONNX Runtime

ONNX Runtime is a general-purpose inference engine with broad operator support and hardware backends. tinyML trades breadth for a smaller, more controllable runtime optimized for deterministic latency and constrained memory budgets.

Embedded ML Frameworks

Embedded solutions (e.g., microcontroller-focused runtimes) excel at minimal footprints but often constrain model families. tinyML sits between these extremes: smaller and more predictable than general-purpose stacks, but more capable than microcontroller-only runtimes.

Educational and Functional

tinyML is both a teaching project and a practical runtime. The codebase is structured to make key ideas easy to study while remaining usable for real deployments. You can learn how modern models work under tight constraints and then ship those same implementations on-device.
